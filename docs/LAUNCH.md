# Запуск сайта на Amvera

Пошаговая инструкция: от первого деплоя на технический адрес до переноса mishale74.ru. Чек-лист — ТЗ §16.

## 0. Что должно быть готово до запуска

| Что                                                                    | Где в коде или у кого                   | Без этого                                     |
| ---------------------------------------------------------------------- | --------------------------------------- | --------------------------------------------- |
| Уведомление в Роскомнадзор (компания в реестре операторов ПДн)         | Компания, 05 раздел 4                   | Штраф за сбор заявок без уведомления          |
| Дата «Цена действует с» = день запуска                                 | Админка → «Комплектации для всех домов» | На сайте цены без даты                        |
| Тексты политики и согласия проверены юристом                           | `/politika`, `/soglasie`                | Риск по 152-ФЗ                                |
| Права на визуализации домов                                            | 05, раздел 11                           | Если права нет — заменить картинки до запуска |
| Ключ API YouGile и колонка «Новая заявка»                              | Переменные Amvera                       | Формы показывают «позвоните нам»              |
| Доступ к регистратору mishale74.ru (и к Tilda, если DNS оставляем там) | Компания                                | Нельзя перенести домен                        |

## DNS сейчас (проверено 07.11.2026)

- DNS-серверы: `ns1.tildadns.com`, `ns2.tildadns.com` — зоной домена управляет Tilda.
- `mishale74.ru A 176.57.67.214`, `www CNAME mishale74.ru`.
- MX и TXT-записей нет — почты на домене нет, переносить кроме сайта нечего.

Два пути, выбрать до запуска:

1. **Перенести DNS к регистратору (рекомендую).** Заранее, за 1–2 дня до запуска: у регистратора включить его DNS, завести те же записи (`A 176.57.67.214`, `www CNAME mishale74.ru`, почтовые MX/TXT, если есть), затем сменить DNS-серверы на регистраторские. Старый сайт продолжает работать на том же адресе, а смена серверов (в зоне .ru — до суток и больше) проходит до дня запуска. В день запуска остаётся поменять записи.
2. **Оставить DNS в Tilda** и менять записи в её панели. Нужен доступ к аккаунту Tilda; заранее проверить, можно ли там добавить TXT `_amvera`.

## 1. Проект в Amvera (один раз)

1. Создать проект, окружение **Node** (настройки возьмутся из `amvera.yml`: Node 22, `npm install`, `npm run build`, запуск на порту 3000). Тариф — «Начальный Плюс» (1 ГБ); если сборка падает по памяти — «Стандартный» (2,5 ГБ).
2. Переменные (раздел «Переменные», ключи — как секреты), по `.env.example`:
   - `LEAD_TARGET=yougile`
   - `YOUGILE_API_KEY`, `YOUGILE_COLUMN_ID`
   - при необходимости `YOUGILE_STICKER_SOURCE_ID`, `YOUGILE_SOURCE_STATES`

   Переменные применяются после перезапуска контейнера. На этапе сборки они недоступны — всё, что нужно при сборке, лежит в `lib/site.ts`.

3. Подключить репозиторий: адрес git-репозитория Amvera добавляется как remote `amvera`. Amvera собирает ветку `master`.

## 2. Деплой

```
git remote add amvera <адрес репозитория Amvera>   # один раз
git push amvera <ветка>:master
```

Каждый `push` выполняется только с разрешения владельца проекта. В репозитории ветки по этапам (`stage-N`), ветки `master` нет — публикуется последняя ветка этапа.

После сборки — проверка технического адреса:

```
npm run smoke -- https://<проект>.<пользователь>.mia0.amvera.tech
```

Ожидаемо: все пункты «ok», `X-Robots-Tag: noindex, nofollow` (технический адрес закрыт от поиска всегда, см. `proxy.ts`).

Затем вручную: отправить заявку с каждой формы (заявка, проект, квиз) и убедиться, что задачи появились в YouGile с источником и UTM. Проверить с телефона.

## 3. День запуска

1. **За сутки** — уменьшить TTL записей домена до 300 секунд (там, где управляется DNS), чтобы переключение и возможный откат прошли быстро.
2. Отдельным коммитом: `lib/site.ts` → `indexable: true` (счётчик Метрики 114223473 уже подключён, список адресов — `components/Metrika.tsx`). Проверки (`npm run check`, `npm run build`, `npm run test:e2e`) — тест «главная закрыта от индексации» при этом нужно обновить в том же коммите.
3. Деплой (раздел 2) и `npm run smoke` на техническом адресе.
4. В Amvera добавить домены `mishale74.ru` и `www.mishale74.ru`, тип подключения HTTPS. Панель покажет записи:
   - для `mishale74.ru` — A-запись и TXT-запись `_amvera`;
   - для `www` — CNAME и TXT `_amvera.www`.

   У регистратора удалить старые A/AAAA-записи Tilda и добавить записи из панели. Обновление DNS — до 24 часов, при TTL 300 — обычно минуты.

5. Когда домен открылся по HTTPS:
   ```
   npm run smoke -- https://mishale74.ru
   ```
   Ожидаемо: все «ok», robots.txt открыт, `X-Robots-Tag: нет`.
6. Тестовая заявка с боевого домена → YouGile.

## 4. После запуска

- Яндекс Вебмастер: добавить сайт (если нет), sitemap `https://mishale74.ru/sitemap.xml`, переобход главной и проектов, регион — Миасс.
- Метрика: цели срабатывают (заявка, квиз, телефон, WhatsApp, фильтр), Вебвизор пишет.
- PageSpeed Insights, мобильный: главная и страница проекта — цели ТЗ §12.
- Ссылки на сайт в Яндекс Бизнесе, 2ГИС, Авито, VK, Telegram, объявлениях Директа — на новые адреса.
- Через 1–2 недели: Вебмастер → «Страницы в поиске», старые адреса заменились новыми, нет ошибок 404.

## 5. Откат

Старый сайт не удаляется месяц после запуска. Если на новом сайте критичная ошибка, которую нельзя исправить за час:

1. Вернуть старые записи там, где сейчас управляется DNS:
   - `mishale74.ru A 176.57.67.214`
   - `www CNAME mishale74.ru`
2. Исправить ошибку, проверить на техническом адресе и повторить шаги 3.4–3.6.
